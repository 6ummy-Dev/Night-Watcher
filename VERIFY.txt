6UMMY — file checklist
======================

After unzipping, the folder must look exactly like this:

  index.html
  README.md
  VERIFY.txt
  CNAME
  robots.txt
  sitemap.xml
  .gitignore
  .well-known/README.txt
  assets/css/style.css
  assets/js/content.js
  assets/js/app.js
  assets/fonts/silkscreen-latin-400-normal.woff2
  assets/fonts/silkscreen-latin-700-normal.woff2
  assets/fonts/OFL.txt
  assets/img/*.png, *.gif
  worker/index.js

Check from inside the folder:

  find . -type f -not -path './.git/*' | sort      (mac / linux)
  dir /s /b                                        (windows)

Then open index.html in a browser.
  - Big 6UMMY wordmark + spec table  ->  all three assets loaded, you're done
  - Unstyled black text on white     ->  assets/css/style.css is misplaced
  - Styled but no table/crate/links  ->  one of the assets/js files is misplaced

Preview the live state:  index.html?live=1
Preview Spanish:         index.html?lang=es

--------------------------------------------------------------
IMPORTANT — dotfiles and the GitHub web uploader
--------------------------------------------------------------
Dragging files into github.com in a browser SILENTLY SKIPS anything
starting with a dot. That means .gitignore, .well-known/ and
assets/img/.gitkeep will not upload that way.

Nothing breaks if they're missing today, but .well-known/ is where
your Brave verification file has to live. Two options:

  A. Use git from the command line (recommended):

       cd 6ummy
       git init
       git add .
       git commit -m "New site"
       git branch -M main
       git remote add origin git@github.com:YOURNAME/6ummy.git
       git push -u origin main

     Create the repo on GitHub EMPTY first - no README, no license,
     no .gitignore - or the first push will conflict.

  B. Drag and drop, then create the dot-files afterwards in the
     GitHub UI with "Add file > Create new file". Typing
     ".well-known/verification.txt" as the filename creates the
     folder and the file in one step.
